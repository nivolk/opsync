# opsync

Агент ведёт ваши задачи в OpenProject так, чтобы команда видела работу: что сделано, что в
работе, что мешает и что дальше. Берёт задачи в работу, пишет по ходу короткие понятные
комментарии, заводит найденные по пути задачи, отправляет на проверку и публикует состояние
проекта. Работает с Claude Code, Codex, Cursor и Claude Desktop.

## Установка

Нужен [uv](https://docs.astral.sh/uv/getting-started/installation/):
`curl -LsSf https://astral.sh/uv/install.sh | sh`

```bash
uv tool install git+https://github.com/nivolk/opsync
opsync setup
```

`setup` спросит адрес OpenProject и токен и подключит агентов, которых найдёт на компьютере.
Потом перезапустите агента.

## Подключить проект

```bash
cd ~/src/мой-проект
opsync init
```

Выберите проект из списка. Появятся `.openproject.yaml` и блок с правилом для агентов в
`AGENTS.md` (или `CLAUDE.md`) — закоммитьте их, и коллегам этот шаг делать не придётся.

## Работа

Говорите агенту обычными словами:

- «Что по спринту?», «На чём мы остановились?»
- «Возьми задачу 104 в работу»
- «104 готова — на проверку»
- «Принято, закрывай 104»
- «Заведи задачу на эту ошибку»
- «Спиши на 104 два часа»
- «Собери отчёт по проекту»

В Claude Code агент с первой минуты сессии знает ваши задачи в работе и что о них писали, а
после каждого коммита — что сделать с задачей. В коммитах он пишет `OP#104`.

## Что увидит команда в OpenProject

- **В ленте задачи** — с чего агент начал, что сделано по ходу, что мешает и от кого ждём,
  что изменилось и как проверить. Короткими фразами, как пишет коллега, без списков файлов.
- **В статусе задачи** — где она: в работе, ждёт, на проверке, закрыта.
- **Новые задачи** — работа, найденная по пути, с описанием «зачем и когда готово».
- **На обзоре проекта** — статус («по плану», «под угрозой») и сводка: сделано за неделю,
  в работе, ждёт, риски, что дальше. В конце спринта — итог новостью.

## Что агент делает сам, а что — с вашего согласия

Сам: берёт в работу задачу, которую делает, пишет заметки о ходе работы, отмечает блокер,
отправляет на проверку после коммита.

Только с вашего согласия: закрывает и переоткрывает задачи, заводит новые, меняет сроки,
двигает много задач сразу, публикует отчёт по проекту. Похожее на пароль или токен в
комментарий не попадёт — opsync его не запишет.

## Обновление

```bash
opsync upgrade
```

`upgrade` ставит последнюю версию с GitHub и обновляет у агентов скилл и уже включённые
хуки (новые хуки без вашего согласия не ставит — включить: `opsync hooks on`). Доступ к
OpenProject и настройки проектов не трогает. После обновления перезапустите агента: скилл,
хуки и MCP-сервер подхватываются при старте сессии.

Затем в каждом подключённом репозитории:

```bash
opsync doctor    # что настроить для новой версии
opsync rules     # обновить блок правил в AGENTS.md / CLAUDE.md
```

и закоммитьте изменения — у коллег они появятся с `git pull`, а `opsync upgrade` каждый
делает у себя сам. Что поменялось и что сделать при переходе — в [CHANGELOG.md](CHANGELOG.md).

Конкретная версия: `uv tool install --force git+https://github.com/nivolk/opsync@v0.3.2`.
Ставили из своей копии репозитория (`uv tool install -e .`) — `upgrade` не нужен: правки
действуют сразу, после новой зависимости — `uv tool install -e . --reinstall`.

---

Если что-то не так — `opsync doctor` покажет, что именно и что сделать. Хуки Claude Code
выключаются `opsync hooks off`.
