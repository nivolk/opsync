# Формат плана

План — YAML-файл с задачами проекта. `opsync apply` приводит OpenProject к нему,
`opsync pull` переносит обратно статусы, `opsync schedule` считает даты.

```yaml
name: myplan                      # имя файла состояния .state/myplan.json

defaults:                         # для всех элементов
  project: my-project             # identifier проекта (из URL /projects/<identifier>)
  type: Задание
  status: Новое                   # только при создании задачи
  priority: Обычное
  assignee: me                    # me или имя / логин / email

projects:                         # создаются, если их нет
  - identifier: my-sub
    name: Мой подпроект
    parent: my-project            # без parent — нужны права администратора и roles: [...]

sprints:                          # API их не создаёт: apply скажет, что завести руками
  - {name: Спринт 1, start: 2026-10-06, finish: 2026-10-16}

calendar:
  hours_per_day: 8                # 0.5d = 4h
  schedule: false                 # true — даты задач без дат считает opsync
  lanes: {Бэкенд: бэкенд, Фронтенд: фронтенд}   # категория → параллельная дорожка
  capacity: {бэкенд: 12}          # часов в день у дорожки
  non_working: {2026-11-04: Перенос выходного}  # apply добавит в календарь (админ)

items:
  - key: epic                     # уникальный ключ — им можно ссылаться: opsync start epic
    type: Сводка задачи
    subject: Название
    defaults: {category: Бэкенд, sprint: Спринт 1}   # для потомков
    children:
      - key: t1
        subject: Задача
        estimate: 6h              # 6h, 0.5d, 30m
        start: 2026-10-07         # start + due — даты закреплены
        due: 2026-10-08
        description: |            # markdown
          ...
      - key: t2
        subject: Следующая
        estimate: 4h
        follows: [t1]             # связь «следует за»
      - key: ms
        type: Веха
        subject: Готово
        date: 2026-10-10
        follows: [t2]

  - id: 84                        # существующая задача: меняются только указанные поля
    parent: epic
```

## Правила

- Сводки (элементы с `children`) получают даты от детей.
- `project`, `category`, `sprint`, `priority`, `assignee`, `version` наследуются от предка и
  `defaults`; `type` и `status` — только из `defaults`.
- Задача без спринта — в бэклоге.
- При каждом `apply` к плану приводятся тема, описание, исполнитель, категория, спринт,
  приоритет, даты, оценка и родитель. Статус — нет: его ведут люди и `opsync start/review/done`.
- Соответствие key → номер задачи — в `.state/<name>.json` рядом с планом. Коммитить вместе
  с планом: без него `apply` на другой машине создаст дубли.

## Даты (`calendar.schedule: true`)

Задачам без `start`/`due` даты ставит opsync:

- оценка раскладывается по рабочим дням исполнителя, `hours_per_day` в день, задачи одного
  исполнителя не пересекаются;
- начало — не раньше начала спринта, своего `start` и дня после предшественников;
- выходные и праздники — из календаря OpenProject и `calendar.non_working`;
- `lanes` — параллельные потоки одного исполнителя (например, два агента под одной учёткой);
- закрытые задачи и задачи с `start` + `due` не двигаются;
- без спринта, `start` и связей — бэклог, без дат.

Повторный `apply` даты не двигает: расчёт не зависит от сегодняшнего дня. Предупреждения
(выход за спринт, перегрузка, веха раньше своих задач) — в `opsync schedule` и `apply`.

## Что настраивается только в интерфейсе OpenProject

`apply` перечислит, если чего-то не хватает, и ничего не создаст:

- категории и типы проекта — «Настройки проекта → Пакеты работ»;
- спринты — «Бэклоги → + Спринт»; подпроектам — «Совместное использование спринта»;
- workflow (какие переходы статусов разрешены).
